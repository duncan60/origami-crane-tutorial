# 紙鶴摺紙教學 · 3D 互動原型

用 3D 摺疊動畫逐步教人摺紙鶴。每一步都可以自由旋轉視角、拖曳進度條停在摺到一半的任何瞬間觀察紙層關係。

**線上版本**：https://duncan60.github.io/origami-crane-tutorial/

這是一個**技術驗證原型**，要驗證的假設是：「3D 摺疊動畫 + 自由旋轉視角 + 進度拖桿，能讓使用者看懂並跟著摺出紙鶴。」

## 開發

```bash
npm install
npm run dev
```

## 摺紙引擎怎麼運作

核心在 [src/fold.ts](src/fold.ts)。

紙張以「攤平座標系」中的多邊形集合表示。每一摺都是**把選定的面沿一條摺線做鏡射**——這是摺平狀態的精確模型；3D 顯示時則把同一個鏡射換成**繞摺線旋轉 0→180 度**，所以動畫全程每個面都保持剛體，紙不會像果凍一樣被拉伸。

支撐整套機制的不變量是：**在完全摺平的狀態下，一個面的 3D 位置等於它攤平座標的直接嵌入**（攤平 `(x, y)` → 世界 `(x, 0, -y)`）。因為鏡射軸在自己的旋轉下不動，摺線的 3D 旋轉軸可以從任一片移動面的變換矩陣推得，即使那一摺是接在同一步驟前一個子摺之後發生的。這讓複合摺（花瓣摺、內翻摺）可以拆成幾個有時間區間的子摺，接續播放而不必特別處理。

摺法定義在 [src/crane.ts](src/crane.ts)，摺線都用**當下攤平狀態的座標**指定——和真實摺紙圖解的讀法一致。要摺哪幾層則用 `layers` 指定，可以用層號（`{ top: 2 }`）或更穩健的「蓋住某個位置的紙層」（`{ at, pick }`）。

### 紙張厚度與破圖

重疊的紙層必須錯開一點才不會互相 z-fighting。這件小事踩過四個坑，最後的結論很簡單：**偏移量 = 紙厚 × √層序**。

`層序`是引擎維護的權威堆疊順序，而且同層號的面保證互不重疊（`__selftest()` 會驗這一點）。所以「重疊 ⇒ 層號不同 ⇒ 偏移量不同」，遮蔽順序必定正確，也不可能 z-fighting。平方根則負責壓縮：第 1 層分開 1 個紙厚，第 40 層只到 6.3 個紙厚，最上層不會浮離身體。

走到這個結論之前試過的三種做法都失敗，記下來免得再犯：

| 做法 | 失敗原因 |
| --- | --- |
| 偏移量 = 紙厚 × 層序（線性） | 40 層讓頸子被推離身體 0.17 單位（模型才 1.4 大），整片穿過翅膀 |
| 局部厚度 = 數有幾個層號較低的面蓋住自己的重心 | 兩個重疊的面用不同取樣點，數出來可能相同（z-fighting）或順序反轉，實測 209 對 |
| 局部厚度 = 重疊關係上的最長鏈 | 鏈會在重疊圖上遊走（頸尖重疊翅膀、翅膀又重疊別處），頸尖算出 19 層而該處實際只有 4 層，頸子浮離身體 |

正確的局部層序是已知的困難問題，原型不需要解它——單調壓縮權威層序就足夠了。

還有一個獨立的坑：**厚度變化要跟著造成它的那一摺**。複合摺的子摺各有時間區間，若用整個步驟的進度統一內插，先落下的紙層偏移量還沒到位，就會穿進下方的紙裡。

### 兩個容易誤判成破圖的角度問題

**翅膀展開角度要接近 90°。** 否則兩片會一上一下呈不對稱角度；相機仰角一旦接近其中一片的平面，那片就被壓成一條線，看起來像有東西穿過紙鶴。接近 90° 時兩片對稱，任何仰角都不會有一片被壓扁。

**頸尾的內翻摺角度維持 45°。** 曾經為了讓頸尾在攤平的步驟更突出而把角度壓平到離水平 28°，結果立起來之後頸子太水平就不像鶴了。45° 的頸尖雖然水平距離（0.67）沒超過翅膀半展幅（0.707），但翅膀是菱形，尖端仍會穿出斜上緣約 0.2 單位，本來就看得見。

### 主控台診斷

```js
__selftest()  // 一次跑完所有幾何不變量：面積守恆、摺平、同層不重疊、厚度合理
__dump(3)     // 第 4 步結束時各層的攤平多邊形
__probe(3, 1) // 該時刻是否確實攤平（摺平狀態下 y 應全為 0）
```

## 值得記下來的一件事

正方基本型（square base）的教學通常畫成「四個角同時往中間塌陷」的複合動作，那在剛體動畫裡很難乾淨呈現。但**沿兩條中線各對摺一次，數學上就等於正方基本型**：紙的四個角確實都落到同一點，紙的中心成為閉合尖角，四條摺邊與紙層結構完全一致。所以前兩步用單純的對摺就能精確表現，不需要任何近似。
